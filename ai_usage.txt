### 2. Чому не спрацював хук для `ai_usage.txt`?

У файлі конфігурації [`.gemini/config/hooks.json`](file:///home/ubuntu/snap/antigravity-cli/common/.gemini/config/hooks.json) було визначено команду:
```bash
echo -e "User:\n$AGY_INPUT\n\nModel:\n$AGY_OUTPUT\n\n---\n" >> ai_usage.txt
```

Хук насправді викликався, але не записав результат у репозиторій з трьох причин:

1. **Робоча директорія (CWD)**: хук запускається з директорії, де лежить сам `hooks.json` (`~/.gemini/config/`). Відносний шлях `>> ai_usage.txt` призвів до запису у файл `~/.gemini/config/ai_usage.txt`, а не в репозиторій [`cs400-course-repo-vkatsel/ai_usage.txt`](file:///home/ubuntu/cs400/cs400-course-repo-vkatsel/ai_usage.txt).
2. **Змінні оточення**: Antigravity не передає змінні `$AGY_INPUT` чи `$AGY_OUTPUT` в `env`. Натомість контекст передається у вигляді JSON на **`stdin`** (включаючи `transcriptPath` та `workspacePaths`). Через це підставлялись пусті рядки.
3. **Shell-контракт**: хуки викликаються через `/bin/sh -c` (dash в Ubuntu), де `echo -e` не інтерпретує escape-послідовності, а `PostInvocation` очікує валідний JSON у `stdout`.

### 1. Форматування граматики та порожні рядки

- **Чому були порожні рядки**: у формальних специфікаціях порожні рядки часто додають для візуального розділення логічних груп правил (структура програми, інструкції, вирази). Проте стандарти EBNF (зокрема ISO/IEC 14977) не вимагають порожніх рядків.
- **Чи так має бути**: граматика може бути записана як компактно, так і з розділенням рядків. У компактному вигляді без зайвих пропусків вона містить рівно 8 правил:

```ebnf
(* Grammar for Practice 3 Language in EBNF *)
program   ::= { statement } exit ;
statement ::= decl | assign ;
decl      ::= "i32" [ "mut" ] ident "{" expr "}" ;
assign    ::= ident ":=" expr ;
exit      ::= "exit" operand ;
expr      ::= term { ( "+" | "-" ) term } ;
term      ::= factor { "*" factor } ;
factor    ::= operand ;
operand   ::= ident | number ;
```
Кожен термінал у лапках (`"i32"`, `"mut"`, `"exit"`, `"{"`, `"}"`, `":="`, `"+"`, `"-"`, `"*"`) повністю відповідає токену з [lexer.py](file:///home/ubuntu/cs400/cs400-course-repo-vkatsel/lexer.py), а `ident` та `number` є лексемами-терміналами.

### Як ці токени використовує парсер (Practice 3)

Парсер споживає цей потік токенів і будує дерево AST:
1. **Службові токени зникають або стають властивостями**:
   - `"i32"`, `"{"`, `"}"` просто перевіряються (`expect`) і не потрапляють у дерево.
   - `"mut"` перетворюється на булевий прапорець `mutable = True` у вузлі `DeclNode`.
   - `":="` перевіряється в присвоєнні, а сам вузол стає `AssignNode`.
   - `"\n"` відкидається — факт кінця рядка означає, що інструкція завершена.
