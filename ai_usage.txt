### 3. Додаткове завдання: Виклики C через `extern fn` (+1.0 бал)

Дозволити оголошувати прототипи зовнішніх C-функцій:
```text
extern fn abs := (i32 v) -> i32
extern fn isqrt := (i32 v) -> i32
```
* **Семантика та обмеження**:
  * Оголошуються в секції функцій (після структур, до інструкцій).
  * Не мають тіла `{ ... }`.
  * Дозволені типи параметрів та результату: **тільки `i32` та `i64`** (жодних `bool` або структур, оскільки ABI передачі структур/булів відрізняється від C).
  * Заборонені імена, які вже використовуються компілятором (`printf`, `scanf`, `main`, методи структур).
* **Генерація коду**:
  * В IR генерується `declare i32 @"abs"(i32 %".1")`.
  * При оптимізації (`--remove-unused`): невикористаний `extern fn` видаляється; якщо є виклик — залишається.
* **Тести**:
  * `tests/ffi/geometry.txt` + `tests/ffi/geometry.c` (збірка `geometry.o` + `geometry.c` через `clang`).
  * Програма в `tests/ok`, що викликає функції з `libc` (`abs`, `llabs`).
  * Щонайменше 9 тестів на помилки в `tests/err/` на всі описані валідації.

### 1. Що робить сама програма `points`?

У файлі `tests/io/points.txt` пишеться програма мовою нашого курсу:

```text
struct Point
{
    i32 x
    i32 y
    fn d2 := () -> i32
    {
        i32 r{x * x + y * y}
        exit r
    }
}
fn report := (Point p, i32 d) -> i32
{
    i32 mut hit{0}
    if p.d2() == d
    {
        print(p)
        hit := 1
    }
    exit hit
}
print("Enter point 1 (x y):")
Point p1{read(), read()}
print("Enter point 2 (x y):")
Point p2{read(), read()}
print("Enter point 3 (x y):")
Point p3{read(), read()}
print("Enter distance squared:")
i32 d{read()}
i32 n{report(p1, d) + report(p2, d) + report(p3, d)}
exit n
```

**Як вона працює:**
1. Оголошено структуру `Point` з полями `x, y` та методом `d2()`, який повертає квадрат відстані до $(0, 0)$ ($x^2 + y^2$).
2. Оголошено функцію `report(p, d)`: якщо `p.d2() == d`, вона друкує точку `print(p)` і повертає `1`, інакше повертає `0`.
3. Основна програма виводить підказки (`print("Enter point 1 (x y):")`) і через `read()` зчитує координати трьох точок ($x$ і $y$ для кожної).
4. Далі зчитує пороговий квадрат відстані `d`.
5. Підсумовує результати викликів `report` і завершується через `exit n` (де $n$ — кількість точок, квадрат відстані яких дорівнює `d`).

### 2. Як програма збирається в нативний бінарник?

Замість запуску через інтерпретатор LLVM JIT (`lli`), ми проходимо повний пайплайн компіляції:
```bash
# 1. Компілятор генерує LLVM IR (.ll)
python3 compiler.py tests/io/points.txt points.ll

# 2. llc компілює LLVM IR у машинний об'єктний файл (.o)
llc -filetype=obj -relocation-model=pic points.ll -o points.o

# 3. clang лінкує об'єктний файл з libc у виконуваний файл points
clang -fPIE points.o -o points
```

**Чому потрібні флаги `-relocation-model=pic` та `-fPIE`?**
* Сучасний Linux вимагає Position Independent Executable (PIE) для безпеки (ASLR).
* Якщо не передати `-relocation-model=pic` в `llc`, то `clang` видасть помилку лінкування: `relocation against symbol ... can not be used when making a PIE object; recompile with -fPIE`.

**Що всередині `points.o`?**
Якщо виконати `nm points.o`, ми побачимо:
* `T Point_d2` — наш скомпільований метод;
* `T user_report` — наша функція;
* `T main` — точка входу;
* `U printf` та `U scanf` — невизначені символи, які лінкер `clang` автоматично підтягує зі стандартної бібліотеки C (`libc.so.6`).
